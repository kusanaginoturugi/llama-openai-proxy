# 仕様

## 入力（xTranslator → proxy）

- `POST /v1/chat/completions`、OpenAI 互換 JSON
- 最初の `role: user` メッセージの `content` を使い、**1 行目をクエリとして捨て、2 行目以降を原文**とみなす
- それ以外のフィールド（`model`、`temperature` など）は無視する

> 要確認: 上の前提は旧実装から引き継いだもの。`OpenAI_ArrayLimit=2` のとき 2 件がどう連結されるか
> （改行区切りか、別メッセージか）は未検証。`--dump` で実リクエストを取って確認する。

## 翻訳の流れ

1. 辞書の元ファイル（SST / local TSV）の mtime・サイズが変わっていれば辞書を作り直す
2. **全文一致**: 原文全体が翻訳メモリにあれば、それを返す（`glossary`）
3. **行単位一致**: 各行を翻訳メモリで引く。全行（空行以外）が解決したら、それを返す（`glossary`）
   - `Spell Tome: <呪文名>` は `呪文の書: <呪文名の訳>` に展開する
4. 未解決の行だけをまとめて LLM に回す（一部だけ解決した場合は `glossary+<model>`）
   - LLM 出力の行数が未解決の行数と合わなければ、部分合成をやめて全文を訳し直す
5. **キャッシュ**: `prompt版数 + model + 未解決テキスト` をキーに、検証を通った訳だけを保存・再利用する（`cache`）

## 翻訳メモリ・用語・例文（`lib/dictionary.rb`）

- 読み込み順 = 優先順: local TSV → ini の並び順の SST → ini にない SST（名前順）。同じ原文は先勝ち
- **翻訳メモリ**: 全エントリ。完全一致 → 大文字小文字を無視した一致の順で引く
- **用語**: 旧 `usable_entry?` の基準（3〜80 文字、7 語以下、改行や `<>` を含まない、文末記号なし、全部小文字ではない）
  - 原文を単語に分けて、左から最長一致（最大 8 語）
  - 1 語の用語を採用するのは、原文で大文字始まりで、かつ「文中にある」か「訳にカタカナを含む」ときだけ（`Speak = 話す` のような誤検出を防ぐ）
  - local TSV の用語は無条件で採用
- **類似例文**: 20〜300 文字で、訳に日本語を含むエントリ。原文と共有する単語の IDF 合計を、例文の語数の平方根で割ってスコアにし、上位 3 件を使う
  - 出現する例文が 400 件を超える単語は、ありふれていて手掛かりにならないので無視する

## プロンプト

TranslateGemma の公式プロンプトの形を土台に、次を足した 1 つの user メッセージにする。

- ルール（行数を保つ、`<mag>` などのプレースホルダを保持、名詞句は名詞句で訳す）
- `Glossary`: `原文 = 訳` の形で最大 40 件
- `Reference translations`: 類似例文を `English:` / `Japanese:` の対で最大 3 件
- 再試行時のみ: 前回の問題点

`temperature=0`、`max_tokens=原文文字数×3`（64〜4096 の範囲に収める）

## 後処理（旧実装から継承）

- コードフェンス、箇条書き・番号、太字、`Japanese:` のようなラベル、`=>` を含む行を削る
- 原文にない `<tag>` を削る
- 行数が違う場合、1 行の原文なら結合し、空行を除いて行数が合うならその形に揃える
- 原文の行末に `.` / `。` がないのに訳の行末に付いていたら削る

## 検証と再試行

次のどれかに当たったら、指摘をプロンプトに足して `XTRANSLATOR_RETRIES` 回まで再試行する。最終的には問題の少ない出力を採用する。

- 行数が原文と違う
- 原文のプレースホルダが欠けている
- 用語集の訳語が出力に含まれていない（空白・`・`・`=` は無視して比較）
- 原文が 3 語以上なのに、出力の半分以上が英字（未翻訳）

問題が残った訳はキャッシュしない。ログのラベルは `<model> (N problems)` になる。

## 失敗時

- upstream が timeout: 原文をそのまま返す（`finish_reason: length`、ラベル `timeout`）。xTranslator は次へ進む
- upstream が 200 以外: そのステータスと本文を返す
- xTranslator 側の切断（`EPIPE` / `ECONNRESET`）: ログだけ出して続行
